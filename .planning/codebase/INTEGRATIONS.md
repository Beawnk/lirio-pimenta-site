# External Integrations

**Analysis Date:** 2026-08-29

## APIs & External Services

**Messaging:**
- WhatsApp (wa.me deep linking)
  - What it's used for: All customer contact flows lead to WhatsApp. Cart → checkout → WhatsApp link with pre-filled order message. Inquiries about products also send to WhatsApp.
  - SDK/Client: None (direct URL integration via `useWhatsApp()` composable)
  - Implementation: `app/composables/useWhatsApp.js` generates `https://wa.me/${WHATSAPP}?text=${encodeURIComponent(message)}` links
  - Configuration: WhatsApp number stored in `app/data/store-info.js` as `WHATSAPP = '5551998073190'`
  - Entry points:
    - `useWhatsApp()` - Core composable with `waLink()`, `greetingLink()`, `consultLink()` functions
    - `buildOrderMsg()` in `app/composables/useCart.js` - Formats order into Markdown message for WhatsApp
  - No auth required (public links, no API key needed)

**Location & Maps:**
- Google Maps (embedded map link)
  - What it's used for: Store location display and direction links
  - Implementation: Direct URL to Google Maps search API: `https://www.google.com/maps/search/?api=1&query=Rua+Ramiro+Barcelos%2C+84%2C+Centro%2C+Viam%C3%A3o%2C+RS`
  - Configuration: `MAPS_URL` in `app/data/store-info.js`
  - No API key needed (public URL, no usage tracking)
  - Used in schema.org JSON-LD as `hasMap` property

**Social Media:**
- Instagram
  - URL: `https://www.instagram.com/lojaliriopimenta/`
  - Stored: `app/data/store-info.js` as `INSTAGRAM` constant
  - No integration beyond direct link (no embed, no API)
- Facebook
  - URL: Not yet defined (`FACEBOOK_URL = ''` in `app/data/store-info.js`)
  - Placeholder for future use

**Design & Fonts:**
- Google Fonts (via CDN)
  - Fonts: Poppins (display), Inter (text)
  - Link tag in `nuxt.config.ts` (`app.head.link`)
  - CDN: `https://fonts.googleapis.com/` and `https://fonts.gstatic.com`
  - No API key, no tracking
  - Preconnect headers for performance

**Schema & SEO:**
- schema.org (JSON-LD)
  - What it's used for: Structured data for search engines (Store/LocalBusiness schema)
  - Implementation: Pure data generation, no external calls
  - Generated by `useLocalBusiness()` in `app/composables/useLocalBusiness.js`
  - Includes: Store name, address, phone, hours, location, social links
  - Injected in `app/pages/index.vue` as `<script type="application/ld+json">`

## Data Storage

**Databases:**
- Not applicable - Phase A uses static data only
- Future (Phase B): Supabase (PostgreSQL + Auth + Storage) mentioned in CLAUDE.md but not yet implemented

**Local Storage:**
- Browser localStorage (client-side only)
  - Keys:
    - `lp_cart` - Shopping cart items (serialized JSON array of `{ id, qty }`)
    - `lp_favs` - Favorites/bookmarks (inferred from store structure, implementation in `app/stores/favorites.js`)
  - Persistence logic:
    - Cart: `app/stores/cart.js` - `persist()` writes to `lp_cart`
    - Favorites: `app/stores/favorites.js` - Similar pattern
  - Hydration: Cart hydrated in plugin `app/plugins/cart.client.js` on `app:suspense:resolve` hook (after SSR hydration)
  - No encryption, no server-side sync

**Static Data Files:**
- `app/data/products.js` - Catalog data (~18 example items): `id, name, cat, img, price (null), available, isNew, desc`
- `app/data/categories.js` - Category definitions: `name, icon, image, desc`
- `app/data/banners.js` - Hero carousel and promo banners
- `app/data/store-info.js` - Store metadata: address, phone, hours, WhatsApp, Instagram, maps URL

**File Storage:**
- Not yet implemented (Phase A)
- Future (Phase B): Cloudflare R2 or Supabase Storage for product images
- Current: Images are pre-optimized `.webp` files in `public/img/`

**Caching:**
- Browser cache via HTTP headers (Cloudflare Pages default)
- No server-side caching layer (static site)
- No Redis or cache service
